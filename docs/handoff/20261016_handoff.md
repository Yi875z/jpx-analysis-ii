# 2026-10-16 ハンドオフ: 回帰テストの時限爆弾で週次実行が停止 → 修正・10/9週を復旧

## 何が起きたか
- 10/16 15:45・17:15 の起動が「Run report rule regression tests」で失敗し、JPX取得まで進まなかった。
  10/9週（10/12 スポーツの日のため金曜 10/16 公表）のレポートが未生成のままだった。
- 失敗メールは「理由ファイルなし」で、メールから原因を読めなかった。

## 原因
- `tests/test_weekly_guards.py::test_already_generated_is_quiet_skip` が 9/25週を固定データにしている一方、
  `main.run_weekly` の停滞判定（①-b）は `date.today()` を読む。10/16 で 9/25 から21日となり、
  閾値 `STALE_ALARM_DAYS = 20` を超えて `stale` に落ちた。本番ロジックは正常で、テストの不備。
- テスト追加時（2026-10-02）は 7日前だったので通っていた。日を追うと必ず落ちる型だった。

## 変更ファイル（commit 44ff67a）
- `main.py`: 停滞判定の「今日」を `_today()` に切り出し。
- `tests/test_weekly_guards.py`: フィクスチャで今日を固定（既定 2026-10-02）。stale の境界テスト2件を追加
  （20日=スキップ / 21日=失敗）。
- `.github/workflows/weekly_fetch.yml`: テスト工程で落ちたら `outputs/last_run_error.txt` に
  `test_failed` と失敗テスト名を書く → 失敗メールの件名・本文に載る。

## 実行コマンドと結果
- `python -m pytest tests/ -q` → 58 passed（ローカル・CI とも）
- `gh workflow run weekly_fetch.yml --ref main` を1回 → run 38906199161 成功。
  week_date 補正 10/16→10/9、レポート生成（11,189文字）、アラート・サマリーメール送信。

## 未解決事項
- テスト失敗時メールの新しい文面は、実際にテストが落ちるまで本番では未確認（ローカル静的確認のみ）。
- Ubuntu 26 への ubuntu-latest 移行（10/19〜）と Node.js 20 廃止の警告が出ている。今回は未対応。

## ロールバック
- `git revert 44ff67a`（テストが再び実日付依存に戻るので非推奨）。

## 再発防止の原則
- 「今日」を読む判定は、テストから日付を差し替えられる形（関数・引数）にする。
  固定日付のテストデータと実日付を混ぜない。
